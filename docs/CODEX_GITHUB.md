# Работа с GitHub

Основной репозиторий: `byShadow64/tg-proxy`. Перед изменением проверьте текущую
ветку, remote, незакоммиченные файлы и актуальные инструкции. Сохраняйте чужую
работу; связанные изменения оформляйте отдельной веткой и reviewable PR.

## Доступ и API

Используйте обычную авторизацию владельца через подходящий подключённый инструмент,
GitHub Desktop или Git. Не извлекайте cookies/токены другого инструмента.
Успешное чтение не доказывает право записи; HTTP 404 не объясняет причину отказа.
Не обходите отказ другим токеном, IP или аккаунтом.

Для 403/429 учитывайте Retry-After, Remaining/Reset и secondary backoff. Ограничивайте
повторы и пагинацию, не опрашивайте rate-limit endpoint непрерывно. Связанные
мутации выполняются последовательно, с паузой не менее секунды в серии.
После неопределённого POST/dispatch сначала проверяется фактическое состояние;
слепой повтор может создать дубликат. Для длительного ожидания используйте события,
когда они доступны, и не учащайте мониторинг без причины.

## Разные поверхности проекта

README и руководства — файлы репозитория. Wiki хранится в отдельном `.wiki.git`.
Pages публикуется из реально настроенного источника сайта. Правка docs не равна
развёртыванию сайта. Домен, права, безопасность и доступ меняются только по
отдельному поручению владельца.

## Выпуски

Сначала проверяются точные source/default SHA, CI, workflow, tag/release и права.
Публикуется один одобренный immutable bundle; EXE не пересобирается для канала.
После Actions проверяются скачиваемые файлы и хеши. Существующие теги и assets
не заменяются. Порядок приведён в [GITHUB_WORKFLOW](GITHUB_WORKFLOW.md).

Токены, пароли, закрытые ключи, профили и необработанные журналы не включаются
в Git или отчёты. Соблюдайте [правило публичных ссылок](GITHUB_CONTENT_POLICY.md).
Соблюдение API-лимитов не является гарантией отсутствия модерации или ограничений.
