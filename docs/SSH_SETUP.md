# Настройка Helper по SSH

Поддерживается в Исходники Windows 1.15.3 и Android 0.1.7-dev. Подключение готового Helper
по IP и установка нового сервера — разные действия. Точные результаты и границы
проверок находятся в [PROJECT_STATE](PROJECT_STATE.md).

## Подключение и согласие

Для уже включённого в registry Helper клиенту достаточно IP: он получает
подписанный descriptor и краткоживущий lease, проверяет pin и не узнаёт старый
private token. Модель допускает любого автоматически зарегистрированного
клиента; это публичный режим владельца, не частное приглашение и не аттестация.
Если IP неизвестен, программа предлагает **явно** настроить VPS по SSH.
Неизвестный адрес сам по себе установку или публикацию сервера не запускает.

1. В Windows откройте **Настройки → Маршруты**, в Android — **Маршруты**.
   Укажите числовой публичный IP VPS и выберите настройку сервера по SSH.
2. Введите SSH-порт и root. Сверьте тип и SHA-256 host key с независимыми
   данными владельца/консоли хостинга. Пароль передаётся только после
   подтверждения точного ключа того же адреса/порта. Смена ключа требует
   повторной проверки, а не автоматического принятия.
3. Отдельно подтвердите доступ зарегистрированным клиентам. Если на VPS уже
   стоит private Helper, требуется второе, первоначально **не отмеченное**
   согласие на его перевод. Публичный режим не включается как побочный эффект
   обновления старого сервера. Не делайте этого для чужого VPS.
4. Установщик проверит root, Ubuntu/Debian и systemd, загрузит встроенный
   проверяемый payload по SFTP, установит зависимости и службы. Исходники не
   клонируются с GitHub во время этой операции. Точный список и SHA-256 входят
   в payload manifest; неожиданные файлы/пути и неверные хеши отклоняются.
5. Успех требует строгого публичного receipt с IP/портом/pin/Helper ID **и**
   независимого подписанного центрального lease с теми же значениями.
   Один exit code SSH, открытый порт или текст в stdout недостаточны.
6. После подтверждения примените настройки. Ранее несохранённые формы,
   отменённые операции и поздние ответы не должны менять рабочий профиль.

Root-пароль существует только в памяти текущей операции; не попадает в командную
строку, SFTP payload, логи, clipboard, saved state, Intent extras или настройки.
Android очищает переданный CharArray. Управляемые закрытые ключи, старые токены
и файлы профиля не включаются в исходники/публичный отчёт.

## Порты и отдельные сертификаты

- SSH: введённый владельцем порт, обычно 22. Установщик не меняет sshd и не
  обходит host-key проверку, пароль или ограничения хостинга.
- TCP/8444: data Helper с прежним pinned TLS-сертификатом; повторная установка
  сохраняет его и private token. Legacy/открытый транспорт не включается.
- TCP/443: отдельный публичный HTTPS endpoint подтверждения IP для registry.
  Нужен CA-сертификат с этим IP в SAN; обычный self-signed certificate не годится.
- TCP/80: HTTP-01 для выдачи/продления короткоживущего IP-сертификата. На первой
  установке порты 80/443 должны быть свободны; чужие web-конфигурации не меняются.
  При повторной установке разрешён только известный собственный 443 endpoint.
  Внешний firewall хостинга должен пропускать необходимые порты. Active UFW
  добавляет лишь нужные отсутствующие собственные правила80/443 и откатывает
  лишь собственные добавления; `--no-firewall` оставляет настройку владельцу.
  Независимые UFW15 и итоговый payload subset прошли; это не настройка внешнего
  firewall у хостинга.

Установщик использует закреплённые Certbot-зависимости с `--require-hashes`,
профиль short-lived (около 160 часов) и таймер продления. Hook проверяет цепочку
CA/IP и обновляет только 443 enrollment certificate, сохраняя 8444 certificate,
ключ и token. Отказ сертификата/registry не переключает клиента на TOFU, HTTP,
redirect или private-network callback. Убедитесь, что renewal действительно
работает: исправный data listener не доказывает доступность нового enrollment.

В публичном режиме data Helper ограничен 32 соединениями и сообщением 2 МиБ.
Перед отправкой целиком резервируется квота сообщения; Telegram получает один
нефрагментированный binary WebSocket frame. По умолчанию на устройство разрешено
4 МиБ/с с burst 2 МиБ, суммарно 16 МиБ/с с burst 4 МиБ. Загрузка к клиенту
учитывается блоками 64 КиБ. Переподключение не сбрасывает квоту: закрытый bucket
сохраняется на весь интервал восстановления burst. Private-token режим сохраняется.
Квотная стоимость каждого сообщения — минимум 4 КиБ: это ограничивает поток мелких
сообщений без отдельного FPS-механизма. Нулевые registered upload frames отклоняются
до отправки. Счётчики трафика показывают фактические байты, а не квотную стоимость.

## Ручной вызов владельца

Публичный режим не является значением по умолчанию у обычного `deploy_helper.sh`.
Проверенный центральный HTTPS-адрес и SPKI ключа подписи получают из доверенного
административного профиля, а не из произвольной ссылки или ответа неизвестного VPS.
После проверки исходников/манифеста локально задайте параметры и выполните:

```sh
sudo bash deploy_helper.sh --registry-mode \
  --registry-url "$REGISTRY_HTTPS" \
  --registry-trust-spki "$REGISTRY_PUBLIC_SPKI" \
  --public-ip "$HELPER_PUBLIC_IP"
```

Перевод уже установленного private Helper дополнительно требует
`--allow-existing-private-upgrade`. Используйте этот флаг только после
сознательного согласия владельца. Для сохранения private Helper не задавайте
`--registry-mode` и параметры registry. Команда выше — инструкция для проверенной
будущей сборки, а не поручение сейчас менять действующий сервер.

## Отмена, сроки и восстановление

Android запускает одну RAM-only foreground `dataSync` задачу с прогрессом и
действием отмены. Пароль не передаётся через Intent. `START_NOT_STICKY` запрещает
восстановление установки после уничтожения процесса; partial wake lock ограничен
12 минутами. Срок install phase — до 600 секунд, общий бюджет — 660 секунд;
подключение, аутентификация, загрузка, чтение и объёмы ответов ограничены отдельно.
Это не бессрочная фоновая операция. Поворот/закрытие UI не создаёт вторую установку.

Отмена прекращает локальную операцию и закрывает её ресурсы. После запуска
удалённых команд потеря SSH или ответа может оставить сервер в изменённом
состоянии. Пишите **«состояние сервера не подтверждено»**, пока повторная проверка
не установит итог; не обещайте atomic rollback. Скрипт сохраняет backup и пытается
восстановить прежние файлы/службы и отключить новую центральную запись. Потерянный
ответ registry может скрывать уже выполненную операцию: агентский ключ сохраняется
для проверки владельцем, а не уничтожается ради видимости чистого отката.
Старые backup/credentials не публикуйте и не удаляйте до подтверждения результата.

## Зависимости и проверка

Android SSH использует JSch 2.28.8 и Bouncy Castle 1.86 с лицензиями и SHA-256
JAR/POM в `android/core/ssh-artifacts.lock.json`; встроенный публичный payload
содержит явно перечисленные исходники, без паролей/ключей/настроек владельца.
Python зависимости Helper/registry/Certbot закреплены хешами в requirements.
Наличие lock/manifest не подменяет аудит зависимостей и проверку готовой APK.

Текущие проверки и их границы описаны в
[PROJECT_STATE.md](PROJECT_STATE.md) и [SECURITY_AUDIT.md](SECURITY_AUDIT.md).
Точный набор payload и его хеши формируются при сборке. Результаты текущей
ревизии указываются в PROJECT_STATE; наличие манифеста не доказывает успешную
установку или обновление реального сервера.
